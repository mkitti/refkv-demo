Image files to Zarr in the browser, with phkv

Paste the URL of an image file, a Zarr or N5 store, a .vzip archive or a .phkv store. Your browser reads its structure, presents it as Zarr without copying its data, and opens it in Neuroglancer (or, for a Sentinel-2 product, on a map).

This Neuroglancer link opens only on this site, in a browser where this page has zarrified the file: the page's service worker answers its reads. The store it keeps is a phkv store (a draft format): download the .phkv and open its URL here, from a server that allows cross-origin reads (CORS), or read it with refkv's Rust crate. The Neuroglancer fork and refkv's Python package read vzip archives, not phkv stores yet, so there is no link to share. The store refers to the original's bytes by URL, so it stays small, and pins each source's size.

This Neuroglancer link names the archive itself (<archive url>|vzip:<path>|zarr3:): share it, and any deployment of the Neuroglancer fork opens it, with no service worker.

In Python

This script builds the same Zarr hierarchy with refkv and opens it with zarr-python. Its header declares its dependencies (PEP 723), so runs it, with uv.

How it works

Zeiss CZI, DICOM, FITS, FLAC (Free Lossless Audio Codec), WMO FM 92 GRIB edition 2 (WMO-No. 306, Manual on Codes, Volume I.2), HDF5, NWB, Imaris IMS, Leica LIF, MP3 (MPEG Layer III audio), MP4 and QuickTime (H.264 and HEVC video, AAC and MP3 audio), MRC2014, Nikon ND2, Hamamatsu NDPI, NIfTI-1 and NIfTI-2, NumPy NPY and NPZ (NEP 1), NRRD (Teem), Akoya QPTIFF, TIFF, OME-TIFF, Aperio SVS and Olympus VSI files, N5, OME-Zarr 0.4 and Zarr v2 stores, and Sentinel-2 SAFE (Level-1C, Level-2A) and safetensors (Hugging Face) products are supported; the format is detected from the file's first bytes, or the store's metadata. A service worker reads the input's structure with a few range requests, writes a phkv store in memory (by spec/zarrify.md), keeps it in the browser's cache, and serves it as plain Zarr at a local URL that any Zarr viewer on this site can open. Pixel data is read from the original only when a viewer asks for it. That link works only here. A phkv store is one file, indexed by a perfect hash, so a reader finds a key in one hop, however many keys it has; this page can open one you host (a .phkv URL).

Part of refkv, reference semantics for key-value storage: specification, implementations and the source of this demo. The Python script is highlighted by highlight.js (BSD-3-Clause).
